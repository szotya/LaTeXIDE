## UI57 double-click review continuation — 2026-11-16

The native drag gap now checks an explicit AppleActionOnDoubleClick value on a
double click: Maximize dispatches performZoom and Minimize dispatches
performMiniaturize. Single/triple clicks and nil, empty, None, Fill or unknown
values keep the previous drag path. A detached view returns before reading the
preference or invoking a window action. This is the accepted narrow review scope;
full system titlebar action parity remains open in #57 / WRA-55.

Three new actual native routing methods use an owned hidden NSWindow subclass.
Its zoom, miniaturize and drag overrides only count calls and retain the original
event; they never call the Window Server implementations. Synthetic events go
directly to the owned view. Tests inject the preference reader, without writing
system preferences, and assert that the window remains hidden, nonkey and nonmain.
The detached control fails if the preference reader is invoked.
